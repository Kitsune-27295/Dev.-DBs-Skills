## Notes on disagreements and nuances across sources

- **Classic Actors (Akka/Erlang) vs. Virtual Actors (Orleans/Dapr):** In classic Akka/Erlang (Source 1), developers explicitly spawn actors, manage actor references (`ActorRef`), and define parent-child supervision trees for lifecycle recovery. In Microsoft Orleans's Virtual Actor model (Source 2), grains are perpetually addressable by domain key and the cluster runtime automatically activates, places, rebalances, deactivates, and restarts them across silos. Both enforce the same core invariant: single-threaded message processing per actor instance with zero shared mutable memory.
