# Sources for the vertical-slice-architecture skill

Retrieved 2026-11-22 via Firecrawl (`firecrawl_scrape`). Statements below summarize the canonical sources and separate architectural rules from author claims.

| # | Source | What the skill takes from it |
|---|---|---|
| 1 | Jimmy Bogard, "Vertical Slice Architecture" (2018-04-19), https://www.jimmybogard.com/vertical-slice-architecture/ | Origin and foundational rule: **"Minimize coupling between slices, and maximize coupling in a slice"**; critique of mock-heavy traditional layered/onion/clean architectures where adding a feature touches many layers and forces unnecessary abstractions (`Controller -> Service -> Repository`); coupling along the axis of change (distinct requests / CQRS commands and queries); per-slice choice of Fowler domain logic patterns (start with Transaction Script or direct query, refactor to rich Domain Model as code smells emerge); rule from Q&A: **"Code sharing is coupling"** — only share validation/logic across slices when it represents the *exact same domain concept*, not merely similar-looking code. |
| 2 | Jimmy Bogard, `ContosoUniversityDotNetCore-Pages` (Reference Repository), https://github.com/jbogard/contosoUniversityDotNetCore-Pages | Concrete reference implementation organizing features vertically with MediatR commands/queries, FluentValidation, AutoMapperprojections directly over EF Core `DbContext` (no repository layer), and vertical slice integration tests running against real database containers (Testcontainers). |
| 3 | Milan Jovanović, "Vertical Slice Architecture in .NET", https://milanjovanovic.tech/blog/vertical-slice-architecture-dotnet | Structuring slices by feature (Request, Handler, Validation, Data Access in one place); combining Vertical Slices with CQRS and the REPR (Request-Endpoint-Response) pattern; handling cross-cutting concerns via MediatR pipeline behaviors; deciding where shared domain logic lives; testing vertical slices end-to-end. |

## Notes on disagreements and nuances across sources

- **Pure VSA (Direct `DbContext`/SQL) vs. VSA + Clean Architecture Domain Core:** Bogard (Sources 1 & 2) eliminates repository and application-service layers entirely, injecting `DbContext` directly into slice handlers and pushing complex mutations into rich Domain Entity methods. Jovanović (Source 3) notes that teams with very rich domain invariants often combine Vertical Slices at the feature/application layer with a shared `Domain` core of Entities and Value Objects. Both agree on eliminating pass-through horizontal service/repository abstractions.
